# Openings and Codex Visual Draft Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Compare a private Codex visual draft with API recognition and display an editable apartment with actual door/window apertures in 3D.

**Architecture:** Versioned domain geometry owns opening spans and wall-piece generation. React owns manual placement/properties and SVG/Three.js rendering; local ignored artifacts hold the private tracing/comparison.

**Tech Stack:** Existing pnpm/TypeScript, Zod, React/SVG, Three.js/R3F, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-17-openings-design.md`

## Global Constraints

- Documentation/commits English; UI English/Russian. Keep private plans, scripts and keys ignored.
- Preserve an exported active document before hot updates. Work in the current checkout.
- No new API call, dependency, HA feature, or architectural accuracy claim.
- Owner confirmed 2.5 m ceiling and centimetres on their plan; other projects still need explicit scale/height.
- Validate, commit and push coherent completed changes to the existing upstream branch.

## Review Focus

- A shared partition must have a usable opening on both faces, rather than a decorative door over solid wall.
- Version 1 data must survive migration; version 2 round-trips opening references.
- Removing a room or changing height must not leave invalid hidden opening data.
- Geometry edits and opening placement must not overwrite a concurrently edited project.
- The private Codex draft and comparison must not enter Git or be presented as unattended API recognition.
