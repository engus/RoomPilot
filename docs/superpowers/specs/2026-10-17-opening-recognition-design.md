# OpenRouter opening recognition

The owner requested automatic doors and windows in both the plan and 3D. Extend the existing OpenRouter image request, retaining other providers' room-only contracts. Also offer an openings-only action on an existing project so corrected room outlines, calibration, ceiling confirmation and manual openings survive recognition.

Provider openings describe two normalized image-coordinate endpoints along each wall aperture. Deterministic geometry attaches the segment to the nearest compatible room edge and, where present, its nearby opposing wall face. One physical aperture has one or two wall-face spans. Heights and window sill heights are nullable in the provider draft: copy readable measurements in metres, otherwise use explicitly disclosed preview defaults (doors 2.2 m; windows 1.5 m high with 0.85 m sill, capped to a known ceiling). Only unknown dimensions may be adjusted to fit; explicitly read dimensions that do not fit are rejected. Width comes from the image segment, not a guessed metric value. These are editable suggestions, not confirmed measurements. Existing project version 2 remains unchanged.

Implementation ruling from live evidence: the initial index/fraction provider contract produced incorrect edge numbers, reversed intervals and unrelated paired faces. Replace model edge arithmetic with endpoint detection. Attach only nearly parallel segments (cross-product ratio <= 0.1) whose endpoints project within the edge (up to 2 pixel tolerance), within 2.5% of image diagonal and, if calibrated, 0.6 m. Paired faces additionally require opposite inward normals, parallelism <= 0.05, and projected endpoint agreement within max(2 pixels, 5% of aperture width). These are draft snapping tolerances, not a guarantee of architectural correctness.

Validate references, bounds, duplicate/overlapping spans and ceiling fit. Invalid individual openings are skipped with warnings without losing valid rooms. Shared faces must represent nearby parallel walls with matching projected intervals; reject unrelated paired faces. Preserve existing openings in openings-only mode, skip conflicting suggestions, and never delete manually placed openings. Empty output is explicit and leaves the project intact. Provider/parse failures leave the editor unchanged. No automatic retry or provider fallback.

The openings-only endpoint accepts a bounded validated project, checks the actual embedded image and its dimensions, sends only that image plus normalized room outlines to OpenRouter, and returns the original project with accepted suggestions appended. It shares the existing origin allowlist, credential checks, single-flight slot and timeout. Do not trust arbitrary client URLs or record image payloads. Reject room-free requests. Applying either response in the UI retains the existing generation/revision guard against stale results.

Show the openings-only button only for OpenRouter, describe that the image and room outlines are sent and existing openings are preserved, and support EN/RU. Recognition does not invent calibration or confirm ceiling height. Full recognition creates an unscaled review draft; 3D still requires scale and confirmed ceiling height. Do not hardcode the owner's plan or manually substitute its tracing for model output.
