# Apartment demo and wall-free zones

The owner requested their Codex-assisted apartment interpretation as the public demo, room renaming, and functional zones within the kitchen/living space and its connected corridor. Use the six-room, ten-opening assisted draft, not the poorer automatic OpenRouter output. The owner explicitly authorized publishing this derived layout for other users; redraw its source illustration in code and do not publish the original image, private exports, provider responses or local paths. The demo opens without API calls and has a calibrated scale and the owner-confirmed 2.5 m ceiling so users can immediately inspect 3D. Room/zone names are localized EN/RU and editable. The owner confirmed the labels on their annotated plan: balcony, parents’ bedroom, living area, kitchen, toilet, corridor, storage and children’s bedroom (number 5 was accidentally skipped). Living/kitchen/corridor are zones of the shared main room. Zone boundaries remain illustrative and editable.

A room describes physical enclosure and owns its wall perimeter. A zone is a named polygon inside one room, with no walls, ceiling or openings of its own. The demo's connected main room contains kitchen, living and corridor zones. Preserve all six room outlines and existing doors/windows. Zones tint the floor in 2D/3D and can be selected from the plan, model or zone panel. Zone area is calculated only when calibrated and never added to or substituted for the room's reported area. Zones need not cover the entire parent room, may share boundaries, must lie entirely within its possibly concave polygon, and sibling interiors cannot overlap.

Users select a room, add a zone by drawing a polygon, finish/cancel, rename, adjust vertices or delete it. The parent remains selected while editing a zone. Invalid shapes, escapes from the parent and overlap are rejected without discarding existing data. Room deletion also removes attached zones. A room boundary edit that would invalidate its zones is rejected with a clear localized explanation. Placing openings still uses physical room edges only. 3D renders zones as flat, slightly raised floor surfaces and highlights the selected one; it never extrudes zone boundaries.

Use project version 3 with required zones: [] and strict migration from versions 1 and 2, keeping their geometry/openings unchanged. Unknown versions are rejected. Full AI recognition replaces geometry with an unzoned draft; openings-only recognition preserves all zones. Existing preference behavior stays unchanged. No AI zone detection, furniture, HA controls or full CAD/shared-wall graph in this extension.

Implementation choices: existing React/SVG and native Three.js tools, no new dependency. Use existing polygon-clipping for robust containment and sibling overlap checks rather than vertex-only tests on concave parents. Add focused domain and browser regressions, run full checks, independently review and publish coherent commits under the standing Git workflow.

Validation decisions: max 200 zones, max 100 vertices each, unique zone IDs and valid parent IDs. Clipping uses an absolute 1e-7 pixel-square tolerance; reversed winding, coincident/nested polygons and concave edge escapes are covered. Every mutation uses the editor revision counter. Changing interface language does not rename edited content; opening a fresh demo chooses that language.
